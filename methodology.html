01

Overall SparkEV Workflow & Architecture

Electric vehicle systems have traditionally operated in silos: driving behavior analysis evaluates driver aggressiveness without accounting for battery degradation; battery management systems display present State-of-Charge without anticipating route-specific stresses; and charging locators recommend stations based solely on physical distance rather than battery longevity or dwell times.

SparkEV addresses these fragmented paradigms by implementing a closed-loop multi-tier decision support system. The operational lifecycle follows two synchronized flows:

Equation (1) — Operational Inference & Decision Support Flow: EV Data → Preprocessing → Feature Engineering → Predictive Intelligence Modules → Explanation / Recommendation → What-If Simulation → User Decision
Equation (2) — Privacy-Preserving Collaborative Learning Flow: Local EV Data → Local Model Training → Model Updates → Federated Aggregation → Shared Model → Personalized Local Model (FedPer)

By decoupling the base representations (universal vehicle electrochemistry) from personalization heads (individual driver quirks, terrain, and habits), SparkEV achieves high accuracy without transmitting a single byte of private GPS or trip history to external cloud endpoints.

Data Ingestion & Hardware Sensing Pipeline

Led by Saravanapriyaa C R (Hardware Lead), the telemetry acquisition framework utilizes on-board hardware components to ingest multi-modal signals from the vehicle’s Controller Area Network (CAN) bus and Battery Management System (BMS).

Hardware Transceiver Gateway

  • • Microcontroller: ESP32 Dual-Core 240MHz
  • • Bus Interface: MCP2515 CAN Controller + TJA1050 Transceiver
  • • Protocol Standard: ISO 15765-4 CAN (11-bit / 500 kbps)
  • • Streaming Protocol: MQTT / JSON over local secure Wi-Fi / WebSocket

External Context Ingestion

  • • Station Infrastructure: OpenChargeMap REST API v3
  • • Weather & Ambient Temp: Open-Meteo API (10-min resolution)
  • • Route Elevation: OSRM / Google Directions Elevation Profile
  • • Electricity Tariffs: Dynamic Time-of-Use (ToU) price feeds

03

Data Preprocessing & Cleansing

Real-world vehicular data contains transmission dropouts, electromagnetic interference on the CAN bus, and sensor quantization noise. The preprocessing pipeline applies:

  • Outlier Filtering via Hampel Identifier: Replaces isolated sensor spikes by computing median absolute deviation (MAD) over a rolling 5-second window: $$\text{MAD} = \text{median}(|x_i - \tilde{x}|)$$
  • Extended Kalman Filter (EKF) SoC Reconstruction: Overcomes Coulomb counting cumulative drift by fusing current integration \(\int I dt\) with an offline Open-Circuit Voltage (OCV) polynomial lookup curve: $$SoC_k = SoC_{k-1} - \frac{\eta \cdot \Delta t}{C_n} I_k + w_k$$ $$V_k = f_{OCV}(SoC_k) - R_0 I_k - V_{RC} + v_k$$
  • Resampling & Dynamic Time Warping: Standardizes heterogeneous sample rates to synchronized 1-second intervals for downstream inference.

Temporal Feature Engineering & Model Development

Led by Shravanthi S (Module 3 Lead), the feature engineering pipeline constructs higher-order temporal indices that capture cumulative electro-thermal damage:

1. Historical SOH Lag Features

Battery degradation exhibits heavy temporal autoregressive dependence. We inject historical lag terms:

Lag Vector = [ SOH_{t-1}, SOH_{t-7}, SOH_{t-30}, \Delta SOH_{7d}, \Delta SOH_{30d} ]

2. Cumulative Thermal Stress Integral (TSI)

Lithium plating and Solid Electrolyte Interphase (SEI) growth accelerate non-linearly when operating outside the 20°C–30°C optimal window:

TSI = \int_0^T \max(0, T_{pack}(t) - 30^\circ\text{C}) \, dt + \gamma \int_0^T \max(0, 5^\circ\text{C} - T_{pack}(t)) \, dt

3. Aggressive Driving Index (ADI)

Quantifies throttle and braking volatility to represent inverter and cell current strain:

ADI = \frac{1}{T} \sum_{k=1}^T \left( \alpha \cdot |\text{Jerk}_k| + \beta \cdot \mathbf{1}_{a_k < -3.0\,\text{m/s}^2} + \lambda \cdot (C_{\text{rate}, k} - 1.5)^+ \right)

Module 1: Personalized Driving Behavior Prediction

Lead: Rithanya K A (CB.SC.U4CSE23140)

Traditional eco-driving systems impose universal rules that ignore driver habits, road elevations, and localized traffic patterns. Module 1 establishes a personalized driver baseline and detects deviations:

  • Input: 10-second rolling sliding windows of vehicle speed, throttle position rate, braking deceleration, and power demand.
  • Classifier: Gradient Boosted Decision Tree (LightGBM) trained to classify driving state into Eco, Normal, or Aggressive.
  • Personal Divergence Metric (\(D_{user}\)): Compares current energy rate \(E_t\) against the user's historical 80th-percentile consumption on equivalent road grades: $$D_{user} = \frac{E_{observed} - \mathbb{E}[E_{user} \mid \text{Grade}, \text{Speed}]}{\sigma(E_{user})}$$
  • Actionable Guidance: When \(D_{user} > 1.64\), the guidance engine triggers non-intrusive in-vehicle HMI alerts (e.g., "Gradual throttle increase recommended on uphill stretch to save 2.4 kWh").

Module 2: Predictive Charging Recommendation

Lead: Irene Divya J (CB.SC.U4CSE23167)

Conventional navigation apps route drivers to the nearest charging station. Module 2 formulates charging as a Multi-Attribute Utility Optimization problem, considering driver itinerary, station queues, pricing, and cell preservation:

Multi-Objective Cost Function

\min_{j \in \mathcal{S},\, SoC_{target}} \mathcal{C}(j) = w_1 \cdot T_{\text{travel}}(j) + w_2 \cdot T_{\text{wait}}(j) + w_3 \cdot \text{Cost}(j) + w_4 \cdot \Psi_{\text{stress}}(P_j, SoC_{target}, T_{\text{pack}})

Where \(\Psi_{\text{stress}}\) penalizes 150kW+ DC charging in ambient temperatures \(>35^\circ\text{C}\) and charges exceeding 80% SoC, where CC-CV transition causes excessive cathode lattice tension.

Smart 80% Cutoff Policy: The model dynamically advises charging to 80% instead of 100% when remaining destination distance is safely within range, reducing session duration by up to 50% while mitigating long-term capacity fade.

Module 3: Battery Health Forecasting & SHAP Explainability

Lead: Shravanthi S (CB.SC.U4CSE23147)

State-of-Health (SOH) quantifies the present usable capacity of the battery relative to its rated factory specification:

SOH_t = \frac{Q_{\text{current, max}}}{Q_{\text{nominal}}} \times 100\%

SparkEV performs two synchronized tasks in Module 3:

  1. Autoregressive SOH Forecaster: Employs an ensemble of temporal XGBoost regressors to predict \(SOH_{t+k}\) over the next 100 to 500 charge-discharge cycles based on engineered lag and degradation vectors.
  2. Risk Scoring Engine: Computes a unified Battery Stress Index \(\mathcal{S} \in [0, 100]\) mapping into discrete tiers: Low Risk (<40), Moderate Risk (40–69), and High Risk (≥70).

SHAP (SHapley Additive exPlanations) Formulation

To provide true explainability, SparkEV computes Shapley values based on cooperative game theory, attributing each feature's contribution to the difference between the actual prediction and the fleet baseline:

\phi_i(x) = \sum_{S \subseteq \mathcal{F} \setminus \{i\}} \frac{|S|!(|\mathcal{F}| - |S| - 1)!}{|\mathcal{F}|!} \left[ f_x(S \cup \{i\}) - f_x(S) \right]

Using the polynomial-time TreeSHAP algorithm, feature attributions for 32 input dimensions are computed in <12 milliseconds on edge hardware. If a vehicle receives a "High Risk" notification, the Natural Language Generator outputs the exact reason: "Frequent DC Fast Charging at >36°C contributed +24.8% to the current degradation rate."

Personalized Federated Learning using FedPer

Lead: Gayathri U (CB.SC.U4CSE23026)

Vehicles operate in diverse geographical regions (cold winters vs hot summers), with drivers exhibiting vastly different acceleration and charging habits. Standard Federated Averaging (FedAvg) forces every client model towards a consensus global mean, which degrades performance for outlier vehicles.

SparkEV solves this heterogeneity with Federated Personalization (FedPer):

The Split Neural Architecture

Every client vehicle network is partitioned into two distinct segments:

1. Base Layers \(f_{\text{base}}(\cdot; \theta)\)
Shared representation layers extracting universal physics, impedance dynamics, and temporal electrochemistry. Synchronized via server federated aggregation.
2. Personal Head \(g_{\text{head}}(\cdot; \phi^k)\)
Client-specific dense classification / regression layers tuned to Driver \(k\)'s personal usage patterns. Stays strictly local on the vehicle; never transmitted.

FedPer Aggregation Algorithm

During communication round \(t\), the federated coordinator performs aggregation strictly on base parameters:

\theta_{t+1} = \sum_{k=1}^K \frac{n_k}{N} \theta_t^k \quad \text{while} \quad \phi_{t+1}^k \leftarrow \phi_t^k - \eta \nabla_{\phi^k} \mathcal{L}_k

This mathematical separation ensures that client-specific traits are preserved indefinitely on each car while improving the shared fleet representation. Communication payloads remain light (<450 KB per model update).

Module 4: What-If Simulation Engine

Rather than constraining the user to an opaque, prescriptive recommendation, the What-If Simulator operates as a forward dynamic model.

Given an arbitrary user hypothesis vector \(\mathbf{x}_{\text{hyp}} = [\text{Style}, \text{Temp}, P_{\text{charger}}, SoC_{\text{target}}]\), the simulator calculates:

  • Thermal Gradient Rise: Predicts battery pack temperature evolution \(\Delta T(t)\) under selected charging C-rates.
  • Equivalent Full Cycles (EFC): Computes cumulative degradation impact using modified Arrhenius and Wöhler fatigue relationships.
  • Trade-Off Exploration: Directly quantifies the compromise between charging convenience and cell lifespan (e.g., "Charging to 100% takes 45 extra minutes and induces 2.3x more degradation than stopping at 80%").
