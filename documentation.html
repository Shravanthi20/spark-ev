Project Overview & System Requirements

SparkEV is built using modern Python frameworks for machine learning, federated coordination, and asynchronous REST streaming. It is engineered to run either in simulation mode on a workstation or directly at the vehicle edge.

Host / Server Requirements

  • • OS: Linux (Ubuntu 22.04+), macOS 13+, or Windows 11
  • • Python: 3.10.x or 3.11.x (tested on 3.11.3)
  • • RAM: 8 GB minimum (16 GB for multi-client FL)
  • • GPU: NVIDIA CUDA 11.8+ / 12.x (optional for accelerated PyTorch training; CPU fallback supported)

Edge / In-Vehicle Hardware

  • • Gateway MCU: ESP32-WROOM-32 (Dual-core 240MHz, 520KB SRAM)
  • • CAN Controller: MCP2515 SPI module with TJA1050 Transceiver
  • • Port Interface: Standard OBD-II Male to DB9 Female (ISO 15765-4)
  • • Optional Edge SBC: Raspberry Pi 4B (4GB) or Jetson Nano

Installation & Setup Instructions

Follow these commands to clone the repository and configure your isolated virtual environment:

Step 1: Clone Repository
git clone https://github.com/Shravanthi20/spark-ev.git
cd spark-ev
Step 2: Create and Activate Virtual Environment
# On Linux / macOS:
python3 -m venv venv
source venv/bin/activate

# On Windows (PowerShell):
python -m venv venv
.\venv\Scripts\Activate.ps1
Step 3: Install Required Dependencies
pip install --upgrade pip
pip install -r requirements.txt
Step 4: Copy Environment Configuration
cp .env.example .env
# Edit .env with your local ports and credentials

API Endpoints & Request / Response Schemas

The SparkEV FastAPI server exposes asynchronous endpoints for edge clients and mobile applications.

POST /api/v1/predict-driving

Evaluates a 10-second rolling telemetry window to classify driving pattern and detect baseline divergence.

  "vehicle_id": "EV-TN-Amrita-01",
  "window_seconds": 10,
  "telemetry": [

    { "timestamp": 1729810001, "speed_kmh": 72.1, "throttle_pct": 82.0, "brake_pressure_bar": 0.0, "power_kw": 34.1 }

}
Response (200 OK):

  "status": "success",

Dataset Details & Preprocessing Scripts

SparkEV models are trained and validated on three primary empirical data repositories:

  • NASA Ames Prognostics Center of Excellence (PCoE) Li-ion Dataset: Cells B0005, B0006, B0007, and B0018 run through continuous charge, discharge, and impedance cycles at room and elevated temperatures until reaching 70% End-of-Life (EOL) capacity.
  • Oxford Battery Degradation Dataset: Eight 740mAh pouch cells tested in thermal chambers under standard dynamic electric vehicle drive cycles (Artemis urban and highway).
  • Amrita EV Telemetry Field Logs: In-situ OBD-II CAN bus recordings collected across electric two-wheelers and passenger vehicles driving on hilly and urban routes around Coimbatore.
Run Dataset Preprocessor & Feature Generator:
python src/module3_battery/feature_engineering.py \
  --input_dir data/raw/nasa_pcoe/ \
  --output_file data/processed/battery_features.parquet \
  --lag_steps 1,7,30

Instructions for Running Each Module

1. Driving Behavior Prediction Module (Mod 1)

Trains the classification model and evaluates driving baseline divergence:

python src/module1_driving/train_driving.py --data_path data/driving_traces.csv
python src/module1_driving/guidance_engine.py --test_stream live

2. Predictive Charging Recommender Module (Mod 2)

Runs the multi-attribute TOPSIS optimizer to recommend stations and charging limits:

python src/module2_charging/recommender.py \
  --current_soc 28 \
  --destination_km 110 \
  --user_lat 11.0168 --user_lon 76.9558

3. Battery Health & SHAP Explainability Module (Mod 3)

Generates battery stress scores, forecasts degradation, and outputs TreeSHAP waterfall charts:

python src/module3_battery/train_battery.py
python src/module3_battery/shap_explainer.py --sample_id 42

4. Federated Learning (FedPer) Cluster Simulation

Spawns a Flower federated coordinator and launches 5 decentralized vehicle clients:

# Terminal 1: Launch FedPer Server
python src/federated_fedper/server.py --rounds 20 --min_clients 5

# Terminal 2: Launch Vehicle Clients Simulation
python src/federated_fedper/simulation.py --num_clients 5

5. Launch FastAPI REST Server 

uvicorn src.api.main:app --host 0.0.0.0 --port 8000 --reload

Access interactive Swagger documentation at: http://localhost:8000/docs

Hardware Integration & CAN Bus Wiring Manual

Lead: Saravanapriyaa C R (CB.SC.U4CSE23149)

To acquire live telemetry directly from vehicle diagnostic ports, connect an ESP32 NodeMCU to the MCP2515 SPI CAN Transceiver according to the pinout below:

ESP32 to MCP2515 Pin Mapping

  • ESP32 GPIO 5 → MCP2515 CS (Chip Select)
  • ESP32 GPIO 18 → MCP2515 SCK (SPI Clock)
  • ESP32 GPIO 23 → MCP2515 MOSI / SI
  • ESP32 GPIO 19 → MCP2515 MISO / SO
  • ESP32 GPIO 21 → MCP2515 INT (Interrupt)
  • ESP32 5V & GND → MCP2515 VCC & GND

MCP2515 to OBD-II Port

  • MCP2515 CAN_H → OBD-II Pin 6 (CAN High)
  • MCP2515 CAN_L → OBD-II Pin 14 (CAN Low)
  • MCP2515 GND → OBD-II Pin 4 / 5 (Signal Ground)
  • * Ensure 120-ohm termination jumper is enabled.

Troubleshooting, Known Limitations & FAQ

Issue: CAN bus initialization fails (Error code: CAN_INIT_FAILED)

Resolution: Verify that the 120-ohm termination jumper on the MCP2515 module is installed. Check that the vehicle ignition is switched to the "ON" or "ACCESSORY" position, as many EV BMS nodes sleep when key-off.

Issue: Flower federated clients fail to connect to server (gRPC timeout)

Resolution: Confirm that port 8080 is open in your local firewall. When running across distinct physical devices, replace 127.0.0.1 with the server's LAN IP address in .env.

Known Research Limitation: Sub-Zero Thermal Plating

Under severe freezing conditions (< -10°C), physical lithium plating dynamics require advanced electrochemical impedance spectroscopy (EIS) measurements which standard OBD-II PIDs do not directly supply. SparkEV relies on conservative heuristic penalties in these ranges.
